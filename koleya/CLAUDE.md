# CLAUDE.md — правила проекта Koleya («Пять футов»)

Читай этот файл целиком перед любой задачей. Потом `docs/ROADMAP.md`, чтобы понять текущий этап.

## Что это
Пошаговая историческая ж/д стратегия. Telegram Mini App (карта, интерфейс) внутри
существующего бота «Билли»: запуск по команде `/koleya`. Своего бота у проекта нет.
MVP: пролог (Царскосельская) и глава 1 (Петербург–Москва).
Геймдизайн — `docs/GDD.md`, архитектура — `docs/ARCHITECTURE.md`.

## Стек
- Монорепо pnpm workspaces, TypeScript strict везде, Node 20+.
- `packages/engine` — чистая игровая логика, без I/O. Vitest.
- `packages/data` — загрузка и валидация `data/*.json` через zod, типы.
- `apps/miniapp` — Vite + Preact + TypeScript, карта на SVG. Без UI-китов.
- `packages/core` — API игры, хранилище (SQLite, better-sqlite3 + drizzle), проверка initData.
  Не зависит ни от библиотеки бота, ни от HTTP-фреймворка.
- `packages/billy-plugin` — тонкий адаптер под стек «Билли» (команда, маршруты, уведомления, викторина).
- `apps/dev-server` — локальный стенд на Fastify с тестовым ботом.
- Линт/формат: ESLint + Prettier. Тесты: Vitest.

## Команды (создать на этапе M0)
- `pnpm i` — установка
- `pnpm dev` — miniapp + server в dev-режиме
- `pnpm test` — все тесты
- `pnpm lint` — линт
- `pnpm check:facts` — проверка исторической базы (см. ниже)

## Жёсткие правила (не нарушать)

1. **Историю не выдумывать.** Любой исторический текст в интерфейсе берётся только из
   `data/facts.json` по id. Если нужного факта нет — не сочиняй, оставь `TODO(fact)` и сообщи.
   Факты со статусом `to_verify` в игре показываются только с пометкой «уточняется»
   и никогда не используются в викторине. Статус `legend` — только как «легенда», с разоблачением.
2. **Прошлое — фактами, настоящее — никак.** Исторические события, в том числе после 1991 года,
   описываются как факты по источникам: даты, решения, названия поездов и проектов («Сапсан» — факт).
   Нельзя: текущее положение дел (что сейчас строится, планы и сроки действующих проектов,
   «к такому-то году ещё не…»), технические параметры современных поездов и проектов,
   программы испытаний, внутренние документы организаций, названия современных компаний
   (писать описательно: «немецкий производитель», «китайские компании»).
   Такие факты помечаются тегом `hsr_history`; исключения из списка запрещённых слов —
   в `data/forbidden_terms.json` (`exceptions`). Вымышленная глава о будущей магистрали —
   только «по мотивам», без реальных цифр. Если задача этого требует — остановись и спроси.
3. **Игровые числа только в `data/balance.json`.** Никаких магических констант в коде.
   Баланс — игровой, не исторический, и в UI не выдаётся за факт.
4. **Engine детерминирован.** Никаких `Math.random`, `Date.now`, сети и файлов внутри
   `packages/engine`. Случайность — только через переданный seedable RNG.
   Каждая механика покрыта тестами.
5. **Сервер — источник истины.** Клиент шлёт действия, сервер применяет engine и хранит состояние.
   Клиент может предсказывать результат для отзывчивости, но не решает.
6. **Telegram initData валидируется на сервере (HMAC)** на каждом запросе. Без исключений.
   Веб-версия (`koleya/web/`) вместо initData проверяет гостевой токен — тоже HMAC на каждом запросе
   (`verifyWebToken`); гостевые id — из отдельного диапазона.
7. Тексты UI на русском, идентификаторы кода на английском. Даты XIX века — в двух стилях:
   «1 (13) ноября 1851».
8. Темы по эпохам через `data-era` (токены в `docs/DESIGN.md`). MVP — «гравюра и чертёж», светлая.
   Цвета и шрифты только из токенов темы, не зашивать в компоненты.
9. Проект бесплатный: никаких платежей, рекламы, платных API по умолчанию. LLM — опционально,
   выключен по умолчанию, игра полностью работает на статичных репликах.
10. Одиночная игра. Не добавлять рейтинги, турниры и мультиплеер, даже если в «Билли» они есть.
11. Код «Билли» трогать минимально: только регистрация модуля. Вся логика — в репо Koleya.
    Перед изменениями в «Билли» — показать дифф и спросить.

## Проверка фактов (`pnpm check:facts`)
Скрипт должен падать, если:
- событие, советник или вопрос викторины ссылается на несуществующий `fact_id`;
- вопрос викторины опирается на факт не со статусом `verified`;
- у факта `verified` нет ни одного источника;
- в `data/` встречаются запрещённые слова из `data/forbidden_terms.json`.

## Как добавить событие
1. Убедись, что нужные факты есть в `data/facts.json` (или добавь со статусом `to_verify`).
2. Опиши событие в `data/chapterN/events.json` по схеме из `docs/ARCHITECTURE.md`.
3. Эффекты — только через типы эффектов engine; новые типы — с тестом.
4. `pnpm check:facts && pnpm test`.

## Рабочий процесс
- Работай маленькими шагами по `docs/ROADMAP.md`, один этап — одна ветка.
- Conventional commits (`feat:`, `fix:`, `data:`, `docs:`).
- Перед завершением задачи: тесты зелёные, линт чистый, ROADMAP отмечен.
